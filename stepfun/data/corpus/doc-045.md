# FP16 的适用边界与显卡上的表现

FP16 把权重和激活都压到半精度，体积是 FP32 的一半，数值范围和精度都介于两者之间。对我们来说它只在 WebGPU 后端上有意义，因为 WASM 没有对应的指令集扩展。

半精度的优势在显卡上最明显。显卡的计算单元本来就是按半精度设计的，FP16 运算的吞吐通常是 FP32 的两倍以上，而且访存量减半，显存带宽的压力也小。

数值稳定性是它的问题。FP16 的有效位数只有十位左右，模长特别大的向量在累加时容易出现精度损失。我们的做法是在池化之后立刻做归一化，把数值范围压回可控区间。

经验上 FP16 和 FP32 在我们评测集上的差距极小，nDCG 几乎完全一致，Recall@10 只差零点几个百分点。这种情况下选 FP16 就是纯粹的性能收益。

但有一个前提：模型的原始数值范围必须落在 FP16 的舒适区。有些模型某些层的激活值会大到溢出，表现是推理结果出现 NaN 或者全是无穷大。遇到这种情况要退回 FP32，而不是硬调阈值。

半精度还有一个存储层面的好处。如果直接用 FP16 算出来的向量写进库，存储量也只有 FP32 的一半，传输开销也跟着降。不过我们没有这么做，因为库里的向量列类型是按浮点声明的，半精度向量写进去要再转换一次，反而多一次开销。精度压缩这件事交给模型侧的量化去做，存储侧保持简单。

我们的默认值策略是 WebGPU 配 FP16，WASM 配 INT8。这个组合是实测出来的：显卡上 FP16 最快，而纯 CPU 环境下 INT8 在体积和速度上都更划算。
