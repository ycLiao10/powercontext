# 向量归一化与距离度量的一致性

归一化是把向量除以自身的模长，映射到单位球面上。我们在浏览器端向量化时统一开启归一化，这一步在模型输出之后、写入数据库之前完成，属于整个链路里最容易被忽略但又最影响结果的位置。

归一化和余弦度量是一对。如果向量已经归一化，用内积算余弦值是等价的，而且省掉了每次比较时的求模开销。这个等价关系是我们在量化版本上把距离计算改成内积等价式的依据。

但有一个前提：写入索引的向量和查询用的向量必须用同一套归一化逻辑。如果文档向量归一化了而查询向量忘了归一化，搜索结果会明显偏离直觉，而且不会报任何错。我们在查询侧封装了一个断言，模型切换之后第一次查询前先跑一次自检。

我们还把归一化做成了幂等的：向量已经接近单位长度时再做一次归一化，结果几乎不变。这个性质让我们可以在不同环节多次调用归一化函数而不担心精度损失，代价只是多一次除法。

值得注意的是，均值池化加归一化的组合对中文长段落不一定稳。段落越长，各句子的向量平均之后越接近整体方向，段落级别的差异被抹平。我们测试发现超过八百字的段落，检索精度明显下降，所以切分时给段落长度设了上限。

结论上，归一化不是一个可选的优化，而是一条必须遵守的约定。代码里只有一个函数负责这件事，其他地方一律调用它，这样就不会出现某个模块偷偷跳过归一化的情况。
