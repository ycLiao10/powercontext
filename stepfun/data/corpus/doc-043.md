# 模型冷启动耗时与预热优化

模型加载的耗时和推理的耗时完全是两回事。加载包含权重读取、解析、计算图构建和推理会话创建，属于冷启动；推理是热路径。把这两种耗时混在一起报，用户会觉得第一次特别慢、之后就正常，但说不清慢在哪。

我们把冷启动单独统计并且单独展示。FP32 权重的加载在测试机上要三秒左右，INT8 不到一秒半，FP16 大约两秒。热路径上单条查询的向量化只要十几毫秒，两者差了两个数量级。

优化冷启动有几条路。最直接的是减小权重体积，量化把文件从九十几 MB 压到二十几 MB，读取时间跟着下降。第二条是避免重复加载，切换模型时如果目标管线已经存在就直接复用。

预热是指在真正使用之前先跑一次无意义的推理，让分配器、缓存和图形管线都进入稳定状态。WebGPU 上这一步尤其重要，第一次推理要编译着色器，不预热的话用户看到的第一条结果会明显更慢。

我们把预热放在加载完成之后、标记就绪之前，代价是多花几十毫秒，换来的是用户第一次搜索就有稳定的延迟。

还有一个容易被忽略的点是本地存储的读取速度。如果权重放在需要跨网络读取的位置，加载耗时会随网络状况剧烈波动。我们坚持同源静态托管，浏览器可以直接命中磁盘缓存。

预热之后的路径完全不需要用户等待，所以界面上模型一旦显示就绪，就可以放心地接受输入。
