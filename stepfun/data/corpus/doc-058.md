# 相关性标注规范与评测集构建

评测集的标注质量决定了所有指标的可靠性。指标实现得再精确，标注是乱的，结论就没有意义。

我们的标注规范很简单：一条查询对应两到四篇相关文档，相关性分两档。判定标准是"这篇文档能不能直接回答查询提出的问题"，而不是"这篇文档谈到了相关的领域"。

这个区分很关键。按宽标准标，"怎么让检索更快"会召回所有提到性能的文档，Recall@K 看起来很高但对产品没有意义。按严标准标，只有一篇文档真的给出了做法，那才是用户需要的。

标注的粒度是段落而不是文档。我们的语料已经切成段落，一篇文档里可能有三段相关，只有切分粒度上的标注才能和检索结果对齐。

争议样例由两个人独立标，不一致的地方讨论后定稿，同时记录下来。这类争议样例是最有价值的部分，它们暴露了查询本身有歧义，而不是标注员水平不够。

评测集的规模我们定在三十条左右。这个规模够看出参数之间的相对趋势，但不够区分两个非常接近的配置。所以我们从来不根据评测集说 A 比 B 好百分之零点五这种结论。

查询文本要像真人输入。混入口语、错别字、省略主语和不完整的句子很重要，太规整的查询会让评测结果偏乐观。我们特意加了几条只有两三个字的短查询。

还有一条纪律：评测集和调参要分离。我们用评测集调参数，同时另存一份留出集，只在最终验证时用一次。否则参数会过拟合到那三十条查询上。
