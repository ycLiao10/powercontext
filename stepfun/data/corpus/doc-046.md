# 量化前后检索质量的对比方法

对比量化前后的检索质量，流程和对比索引参数时是一样的：同一份标注查询、同一套语料、同一批参数，只是换了推理精度。唯一的变量必须是精度，其它任何差异都会污染结论。

我们的做法是建两套集合，分别存 FP32 和 INT8 的向量，集合名带上精度后缀。这样两条路径在库里是隔离的，切换的时候不需要重建任何东西。

需要注意的是查询向量也要用同一个精度计算。拿 FP32 的查询向量去搜 INT8 的索引，扰动会叠加，测出来的召回下降比真实情况更严重。这个错误我们犯过一次，测出量化掉了十个点的召回，差点否掉量化方案。

数据的稳定性上，三十条查询的评测集对两个点的差异其实没有统计意义。我们的做法是看方向而不是看具体数值：量化后的召回是否在大多数查询上一致地略微偏低，而不是在个别查询上剧烈波动。

我们最终记录的三个指标是 Recall@10、nDCG@10 和向量自身的余弦相似度。最后一个指标其实是原因而不是结果，它帮助我们判断损失来自模型输出还是来自索引侧。

结论是 INT8 量化在本项目上是可接受的：召回下降两个点以内，体积降到四分之一，加载和吞吐都有明显改善。这个结论只在当前语料和当前模型上成立，换模型必须重测。
