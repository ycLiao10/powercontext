# 模型体积、压缩比与首次加载体验

三个模型的 FP32 权重都在九十几 MB 到一百三十几 MB 之间，这样的文件对浏览器端来说不算小，首次加载时能明显感觉到等待。

压缩比是这么算的：用 FP32 的字节数除以压缩后文件的字节数。我们的数据里 FP16 稳定在二倍左右，INT8 在三点九三到三点九七之间，差异来自模型本身的结构。

体积带来两个直接后果。一是下载时间，在慢速网络下九十几 MB 和二十几 MB 的差别是几十秒；二是内存占用，权重、计算图和推理会话同时在内存里，FP32 版本光权重就要占掉近一百 MB。

除了量化，我们还做了两件事。一是给模型目录的静态资源配置长缓存，用户第二次打开时权重直接来自浏览器磁盘缓存，加载时间从三秒降到不到一秒。二是把三个模型的权重分开按需加载，不在启动时预取全部。

有一个反直觉的观察：模型文件即使已经在缓存里，加载耗时仍然接近一秒半，因为解析 ONNX 计算图和创建会话的开销是固定的，跟文件从哪来无关。所以优化加载时间的上限就在这一步。

真要再快就得换一个更小的模型，而不是在同一个模型上想办法。all-MiniLM-L6-v2 的权重比 bge-small 系列小一圈，但中文效果差不少，我们最终还是把中文的默认模型定在 bge-small-zh-v1.5 上。
