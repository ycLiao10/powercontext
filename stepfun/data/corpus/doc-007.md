# 本地开发环境的初始化流程

我们把 seekdb 的初始化收敛成一个脚本，顺序是：等待服务就绪、创建数据库、导入演示语料、建立集合、灌入向量、刷新索引。任何一步失败都在同一位置停下并打印可读的中文提示，不做自动跳过，否则错误会被推到很后面才暴露。

就绪判断不只看端口通不通，还要求版本号查询返回非空并且能拿到版本字符串。只探端口的话，第一次连接经常撞上选主未完成，报一个语焉不详的连接异常，脚本还得靠固定等待硬扛，机器慢一点就还是失败。

演示语料是仓库里语料目录下的 markdown 文件，每个文件一篇文档，以井号加标题开头，后面是若干自然段。导入时按空行切段，每一段单独成条记录，这样全文索引能命中段落级的词，段落长度也不会超过嵌入模型的有效输入长度。

灌入向量这一步放在浏览器端做，因为向量由本地模型在用户设备上计算，服务端不参与任何嵌入运算。脚本会把向量、原文和元数据一起提交，写完立刻调用一次索引刷新，让新文档马上可检索，不需要等后台合并。

刷新之后我们会跑一次冒烟检索，用几个固定查询确认能同时命中向量和全文两条路径。如果只跑向量路能出结果、全文路恒为空，那多半是分词器配置或者刷新没有真正生效，而不是语料本身没有关键词。

整个脚本是幂等的，重复执行不会产生重复数据。集合按名字判断存在与否，已经存在就直接复用；文档写入走覆盖语义。只有显式传清理参数时才会删表重建，这个开关在持续集成里是默认关闭的。

语料文件放在仓库的语料目录下，前端通过静态服务按文件名读取，这套路径也被演示语料的加载按钮复用，改目录时要注意两边同步，否则演示按钮会静默地读不到任何文件。
