# 向量索引里的删除与更新

向量索引的删除比关系表麻烦。关系表删一行就是打一个删除标记，读的时候跳过；图索引里删掉一个节点，挂在它上面的入边不会自动消失，那些边会指向一个已经不存在的目标。

处理办法是墓碑标记。删除时把节点标成已删除但保留它的边，搜索时遇到墓碑节点跳过它、但仍然沿着它的边继续走。这样图结构保持连通，召回不会塌掉，代价是删除过的节点仍然占着内存。

因为这个机制，索引里存的东西只增不减。我们测试过反复删除再导入同一批文档，索引的常驻内存比初始状态高了百分之十几，说明墓碑节点在累积。索引内部的紧凑化会回收一部分，但触发条件并不明确。

更新一条文档在我们的场景里其实是删除加插入。老的向量被标成墓碑，新向量作为新节点进图，然后通过更多的新边把新节点连进来。频繁更新同一批文档会让图在局部反复重建，质量会慢慢下降。

我们的应对办法是控制更新粒度。语料更新按批次来，每批提交前先把该批涉及的旧文档全量删掉再写入，而不是逐条交替删除和插入。交替操作会让同一时刻图里存在大量半新半旧的连接，召回波动明显。

还有一个变通办法：文档正文不变就只更新元数据，不动向量。我们把元数据单独放在 JSON 列里，向量列保持原样，这样改标题、改标签这类高频操作完全不会碰到索引，也就不存在墓碑累积的问题。
