# 检索指令前缀对召回的影响

bge 系列模型在检索任务上有一个约定：查询端要拼接一段指令前缀，文档端不拼。这个前缀的作用是把查询的表示拉向检索任务在训练时的分布。

bge-small-zh-v1.5 的前缀是"为这个句子生成表示以用于检索相关文章："，我们把它放在模型注册表里，由前端的检索流程统一拼接。文档向量化时不加前缀，两侧的处理是不对称的。

漏掉前缀的后果不会报错，只是召回变差。我们做过一次对照：带前缀时 Recall@10 是 0.86，不带前缀掉到 0.79，掉的主要是那些比较抽象的语义型查询，精确匹配型查询几乎不受影响。

这个错误很隐蔽，因为检索照常返回结果，只是排序略微变化。如果没有标注集做对照，很容易被当成模型本身的误差而忽略过去。

前缀的长度也会影响效果。指令太长会让短查询的语义被稀释，我们试过用完整的自然语言描述替代固定前缀，结果反而不如固定的短串稳定。所以前缀一旦定下来就写死在注册表里，不做动态拼接。

还有一个容易忽略的点是前缀不参与入库。前缀只在生成查询向量的那一刻拼接，文档侧写进库的是裸文本算出来的向量。如果误把带前缀的文本拿去灌库，文档侧和查询侧的分布就不一致了，召回会明显下降，而这种错误在界面上完全看不出来。

模型切换时必须确认前缀也跟着换，否则就会出现文档端和查询端处理不对称的问题，而这类问题只能靠标注集发现。
