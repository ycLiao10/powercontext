# 全文索引的重建与词典扩展

全文索引一旦建好，词典和切词结果就固化在索引里了。想让新词能被检索到，只有重建索引这一条路，没有在线增量加词典的接口。

重建的成本取决于文档量。我们在一千五百篇的语料上实测，全文索引重建大约两分半，其中大部分时间花在切词上而不是写数据上。切词是 CPU 密集的，而且词典越长越慢。

自定义词典是最常见的重建理由。我们整理过一份项目词表，里面有三十多个内部代号和产品名，每次扩充词表都要跟着重建一次。折中办法是分两步：先把新增词加入自定义词典，同时在正文里用空格把这些词包起来，让基础分词器也能识别，重建可以等到词表积累到一个批次再做。

另一个办法是在文档层面规避。新词入库时同时写入一个别名字段，别名字段按空格分词并挂一个独立索引，用 space 分词器处理。这样新词走别名的索引，原文走 IK 的索引，两条路在混合检索里各自召回。

我们没有选这条路，因为它把索引结构复杂化了。别名方案要等词表稳定之后才值得上，前期用重建解决更简单。

判断是否需要重建有个简单的检验：拿一个新词去查，如果命中数为零但库里确实有包含这个词的文档，那就需要重建。日常的冒烟测试里我们放了几个版本号作为探针词。
