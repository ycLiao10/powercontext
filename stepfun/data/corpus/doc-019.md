# 租户资源单元的规格怎么给

租户的资源通过资源单元描述，本质是把 server 上的一部分 CPU 和内存切出来给这个租户用。CPU 规格用最小和最大并发数两个值表达，低于最小值时资源闲置，高于最大值时请求要排队等待；内存则相对固定，超出就是真的内存不足。

我们最终把最小规格设成 2 核、最大规格 8 核、内存 8G。最小规格压低是有意的，因为知识库平时查询稀疏，把常驻额度压到最小可以把机器让给同实例的其它业务；最大规格则留得宽裕，这样用户一次导入上千篇文档时，写入请求不会因为并发额度不够而排队。

内存还有一个百分比参数，用来决定租户可以占用 server 内存的上限比例。设成绝对值在共享实例上比较危险，因为 server 上其它租户的用量是波动的；用百分比的话这个租户永远只占自己那一份，边界更清晰。

规格调整是租户级操作，需要管理员权限，而且不是立刻生效。调整之后新建的会话才会按新规格分配资源，已经建立的连接仍然挂在旧的资源池里。这就是我们统一在切换租户时直接重建客户端连接的原因之一。

租户级参数和资源规格是两套东西。规格决定能给多少资源，参数决定数据库内部怎么用这些资源，比如并发度、日志刷盘策略和内存分配比例。排查慢查询时先确认规格给够了，再去调参数，顺序反了会白花很多时间。

还有一个反直觉的经验：规格上限给高之后，租户之间的隔离其实变弱了。共享资源池被这个租户占用的比例上升了，它在抢占 CPU 时的优先级也会更高。我们在共享实例上把实验租户的最大规格压到生产租户的一半，就是为了让实验环境的抖动不会传导到正式数据。
