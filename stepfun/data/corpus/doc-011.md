# 欧氏距离 L2 的适用场景与陷阱

欧氏距离衡量两个向量在空间中的直线距离，值越小越相似。和余弦不同，它对向量长度是敏感的，两条语义相同但表述长度差异很大的文本，编码出的向量模长可能差一倍，欧氏距离就会把这种差异当成不相似。

L2 适合的场景是特征本身有明确绝对量纲的场合，比如图像的像素强度、音频的能量包络，或者以推荐点击向量为输入的召回模型。这些场景里"数值接近"本身就意味着相似，不需要考虑方向。

在文本嵌入上我们不建议用 L2。中文短查询和长文档的模长差异很明显，实测下来 L2 排序会把长文档系统性地往前推，nDCG 掉得比余弦明显。这和推荐场景的直觉正好相反，搜索场景下用户想要的是内容匹配，不是长度匹配。

另一个坑是 L2 和归一化的组合。如果建索引时向量没有归一化，查询向量却做了归一化，两边根本不在同一个球面上，算出来的距离没有意义。我们在建表时就把"写入的向量必须已归一化"写进了接口校验，避免脏数据混进来。

L2 的第三个特性是对数值的绝对尺度敏感。浮点误差在两个向量模长很大时会被放大，比较结果可能因为最后几位不稳定。我们曾经见过同一批查询跑两次得到顺序不同的结果，追查下来是向量里混进了一个数量级明显偏大的分量。

结论是：我们的知识库用余弦，需要用 L2 时单独建一个集合，不要在同一张表里混用两种度量。度量参数在建集合时确定，中途切换意味着整表重建，这个代价必须提前想清楚。
