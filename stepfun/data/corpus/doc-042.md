# ONNX Runtime Web 运行时的自托管

onnxruntime-web 的 wasm 运行时是运行时动态加载的，如果让它走 CDN，就等于在浏览器里引入了一个外部依赖，违反了数据不出端的约束，在内网环境下也会直接不可用。

所以我们把运行时文件复制到自己的静态目录，并通过 wasmPaths 指定这个前缀。目录里有一整套变体：纯 wasm、wasm 加 SIMD、wasm 加线程、jsep 也就是 WebGPU 后端、jsPI 变体，还有各自的 bundle 压缩版。

选错变体会以很难看的方式失败。浏览器根据自己支持的能力去请求对应的文件，如果目录里缺了某个变体，请求会 404，报错信息却是指向模型加载失败的。把整套文件都复制过去是最省事的做法。

另外跨源隔离的响应头也要配。启用多线程的 wasm 变体需要页面在跨源隔离状态下运行，否则 SharedArrayBuffer 不可用，浏览器会拒绝实例化线程数组。

我们把复制运行时这件事做成一个构建步骤，挂在前端构建之前执行。手工复制过一次之后忘了加进构建脚本，CI 环境里就出现了只有部分变体的情况，本地却完全正常。

版本对齐也是一件要盯的事。运行时的文件路径由前缀指定，但真正被加载的是前缀下按能力匹配出来的那一个文件。我们把运行时目录的版本记在前缀的路径里，这样前端和运行时不会各用各的版本，出现行为差异时也一眼能看出是哪个环节的问题。

最后是缓存策略。这些运行时文件是带版本号的静态资源，我们给它们设了长缓存，同时保证文件名带哈希，这样内容变了文件名也会变，不会出现新旧版本混用的诡异问题。
