# 增量导入的幂等性设计

导入必须可重复执行。这不只是为了方便，出错重试、断网续传、用户手滑点两次导入，全都要求同样的输入产生同样的结果。

我们的实现是 upsert，用文档 id 作为主键，重复写入覆盖而不是新增。id 由内容派生，具体是文件路径加上段落序号，同一个文件的同一个段落永远得到同一个 id。

派生规则必须稳定。如果 id 里混进了会变化的量，比如导入时间或者随机数，那么第二次导入就会生成一批新文档，旧文档以墓碑形式留在索引里，索引越用越臃肿。

id 也要能区分不同模型下的同一段文本。我们把模型标识编码进 id 的前缀，这样切换模型重建集合时不会和旧集合的数据串味。

元数据的处理要小心。我们只把标题、来源文件这些稳定的信息放进元数据，不放时间戳，因为元数据变了就等于文档变了，upsert 会重新走一遍删除加插入的流程。

导入脚本本身也要幂等。我们用的是先查存在再决定写不写的逻辑，但为了避免竞态，最终还是用 upsert 兜底。

这套设计带来一个额外的好处：重建集合之后可以直接重放之前的导入序列，结果和原来完全一致，不需要维护一份状态文件来记录哪些已经导过了。
