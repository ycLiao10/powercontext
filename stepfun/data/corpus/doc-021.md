# 数据不出端与本地推理的边界

"数据不出端"是一个承诺，要兑现它必须逐条检查数据可能流出去的所有路径，而不只是确认模型是本地的。

第一条路径是模型权重。Transformers.js 默认允许从远端拉取权重，我们必须显式关掉这个行为，把加载路径固定到自己的静态目录。

第二条路径是运行时。onnxruntime-web 的 wasm 运行时如果走 CDN，同样是一个外部依赖，而且它带着版本升级的风险。我们把它复制到本地静态目录，由构建脚本保证和前端版本一致。

第三条路径是推理接口。服务端没有任何 embedding 代码，SDK 的内置向量函数也被显式置空。向量由浏览器算完再通过本机 HTTP 传给桥接服务，中间不经过任何第三方推理。

第四条路径是遥测和统计。浏览器里的统计脚本默认会把数据发到外部服务，我们的页面上不引入任何这类脚本。

第五条路径最容易漏掉：用户主动分享。知识库可以导出，导出的文件会离开设备。这不是泄漏，但必须由用户显式触发，并且要有清晰提示。

我们做了一次验证，在浏览器里拦截全部网络请求，确认除了本机地址之外没有任何外部域名被访问。这个验证脚本挂在冒烟测试里，每次发布前跑一遍。

边界之外仍然存在两类外部交互：一是浏览器自身的更新，二是操作系统的遥测。这些不在应用的控制范围内，但知道这一点很重要，免得出问题时往错误的方向查。

端侧的另一层含义是数据库。数据库跑在本机，但它是明文存储的，所以机器本身的安全性就是数据的最终边界。我们不做应用层加密，因为密钥也在同一台机器上，加密只是增加复杂度而不增加安全性。
