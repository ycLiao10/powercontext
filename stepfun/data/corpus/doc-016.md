# 数据最小化、本地存储与导出控制

端侧方案的一个隐含承诺是数据不出端，但"不出端"只解决了传输路径的问题，设备上仍然留着一份完整语料，浏览器缓存、日志和临时文件里也可能有残留。

我们先做的是数据最小化。入库的元数据只有标题、来源文件和段落序号，不记录用户是谁、什么时候导入的、从哪个绝对路径来的。来源路径只保留文件名，完整路径不进库。

第二条是浏览器存储。模型权重和向量都可以从语料重新生成，所以不给它们做持久化缓存。只有模型权重因为体积大、走 HTTP 缓存比较划算，其余一律不落盘。

第三条是日志。桥接服务原本会把请求体写进调试日志，我们把这行去掉了。向量本身不算敏感，但原文是用户的私有数据，写进日志文件就等于在磁盘上留了副本。

导出是另一个方向。知识库要能被用户拿走，导出功能是刚需，但导出必须是显式操作：用户点了才导出，导出的文件里带着来源标识，撤回之后可以据此定位。

我们不给库加自动清理的定时任务。个人知识库的语料通常是几百篇，占用空间很小，而定时清理有可能误删用户以为还在的东西。不删除比删除更安全。

还有一个容易忽略的点是浏览器扩展和开发者工具。用户自己在本地看到自己的数据没有问题，但如果页面被嵌进第三方环境，扩展是可以读取页面数据的。我们不做跨域嵌入，也不允许加载第三方脚本。

这些措施加起来的效果是：设备上存在一份可重建的原文副本，没有第二份副本，没有日志里的副本，也没有自动消失的风险。
