# 模型许可、权重来源与依赖治理

端侧方案常用开源模型，但开源不等于没有约束，许可条款是必须逐个确认的工程前提。

我们注册表里的三个模型，bge-small 系列是 MIT，all-MiniLM-L6-v2 是 Apache-2.0。MIT 和 Apache-2.0 都允许商用和再分发，对我们的使用场景没有额外负担，但每次换模型这一条都必须重新确认。

Apache-2.0 有个容易被忽略的条款：如果用它的模型做了对外提供的服务，需要在说明里注明使用了该模型，并且要给出 NOTICE 文件的内容。我们的做法是在界面的关于页面里列出模型名称、来源链接和许可类型。

权重的来源也要记录。我们通过一个镜像站获取权重，脚本把每个文件的 sha256 和字节数记进清单。这样做有两个价值：一是能验证下载的完整性，二是将来需要复现环境时，知道确切的版本和内容。

清单同时充当依赖清单。它记录了每个精度对应的文件名、体积和压缩比，避免了"哪个文件是 q8"这类问题被反复问。

依赖治理的另一半是前端包。onnxruntime-web 和 transformers 这两个包是核心依赖，但它们体积都不小，加载时间受它们影响。我们的原则是锁死版本，升级时单独提一次，升级后重跑质量评测和性能基准。

模型仓库里还有一个容易出问题的地方：权重目录被加进了忽略列表，仓库里只保留清单和获取脚本。好处是仓库不会因为几十兆的二进制文件变得臃肿，代价是换一台机器要重新获取。

我们另外准备了一份合规清单，记录每个模型的许可、训练数据来源的公开说明、以及是否允许商用。新增模型时这张表必须同步更新，没有登记的模型不允许进入注册表。
