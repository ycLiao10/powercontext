# ngram 分词器的适用场景

ngram 是另一类中文分词器，它不做词典匹配，而是把文本切成固定长度的字符片段，默认是二元组，也就是相邻两个字符作为一个词元。它的最大优势是不依赖词典，新词、型号、项目代号一律不会被切错。

这正是 IK 的软肋。IK 依赖词典，遇到词典里没有的专有名词只能靠自定义词典补，补不全就会切错。我们有一批技术文档里全是版本号和内部项目代号，IK 的 smart 模式会把它们切得很碎，而 ngram 完全不关心一个词是什么。

ngram 的代价是索引体积和打分质量。索引里存的是大量二字组，词元数量比 IK 多一个数量级，倒排链更长，BM25 打分时长文档归一化的影响也更明显。我们实测过在五千篇语料上，ngram 索引占用的空间大约是 IK 的三倍。

打分上的差异更关键。ngram 把"向量检索"切成"向量"、"量检"、"检索"，用户的查询"向量检索"也会被切成同样的三组，所以能匹配上；但语义上的近义词完全无法体现，而 IK 的词级匹配配合同义词扩展在这点上更强。

我们的做法是按场景切换：通用中文知识库用 IK，遇到词典覆盖不到的专有名词密集的场景用 ngram。切换分词器必须重建全文索引，因为索引里的切词结果已经固化了。

还有一个折中做法是保留 IK 但扩充自定义词典，把我们语料里出现的高频专有名词整理成一份词表加进去。相比直接切到 ngram，索引体积只涨了一点，分词质量却接近，这是目前性价比最高的方案。
