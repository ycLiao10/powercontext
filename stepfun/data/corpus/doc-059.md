# 数据源接入、切分策略与记忆分层

知识库的第一道工序是接入。数据源可能是本地目录里的 markdown，也可能是从别处导出的文本，形态不一样，但最终都要归一成"一段文本加一组元数据"。

我们目前只支持本地文件，理由是端侧方案的前提就是数据不出端，支持远程源就意味着要处理凭证和传输安全，复杂度完全不同。

切分策略直接决定检索质量的上限。我们的规则是按空行切段，同时给单段字数设上限八百字，下限不做要求。超过上限的段落要么切断要么丢弃，切断的位置我们按句子边界找。

切断是有代价的。断开的半句话在模型那里语义残缺，召回之后用户看到半截论述，体验很差，所以我们的策略其实是尽量不切断，实在太长的段落才切。

段落长度还需要匹配嵌入模型的有效输入长度。超过之后模型会截断，截断掉的内容对向量没有任何贡献，检索时自然也找不到，等于白白浪费了一段正文。

元数据要保持精简，只放标题、来源文件和段落序号这些稳定信息。任何会变的值放进去都会导致文档被判定为发生变更，进而触发一次无谓的向量重算。

记忆分层的思路是把不同性质的东西分开存。原始文档是一层，它是事实来源，可以随时核对和撤回。文档摘要和索引是第二层，它们是从原文派生的，可以随时重建。用户画像和会话历史是第三层，更新频率和保留周期都和前两层不同。

分层的意义在于撤回。只要原始文档还在，摘要和向量就都可以重新算出来；反之如果把派生结果当成唯一来源，源文档一旦失效就无法自证。

我们这套设计目前只做了前两层。第三层属于产品形态的范畴，不在检索链路上，先留着。
